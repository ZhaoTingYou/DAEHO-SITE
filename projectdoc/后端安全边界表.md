## 已处理的安全项

1. API key 从普通字符串比较改为常量时间比较，降低 timing side-channel。
2. 后台登录增加失败限流：15 分钟内同来源失败 5 次，锁定 15 分钟。
3. 公开询单接口增加字段长度上限和 64KB JSON 请求体上限。
4. 后台 JSON 写接口增加 1MB 请求体上限，CMS 导入增加 5MB 请求体上限。
5. 媒体上传统一限制为 GIF/JPEG/PNG/WEBP，单张 20MB 内，扩展名和 MIME 同时校验。
6. 禁止后台上传 SVG，避免同源静态 SVG 带来的脚本执行风险。

## 仍需按部署策略处理的残余风险

1. 后台是单管理员模型，没有用户级 RBAC 和操作审计。若以后多人维护，需要增加管理员账户表、角色、审计日志。
2. 登录限流是进程内存实现；多实例/serverless 环境下不是全局限流。生产建议接入网关/WAF、Vercel Firewall 或 Redis 级限流。
3. 公开询单没有验证码或 IP 级速率限制。字段和体积已限制，但仍可能被批量提交；生产建议加边缘限流或验证码。
4. 后台 API 的 session 写请求额外校验同源 `Origin`；Server Action 仍依赖 httpOnly + SameSite=Lax cookie，没有独立 CSRF token。若后台暴露在复杂同站子域环境，建议增加 CSRF token。
5. 媒体 DELETE 当前删除数据库记录，不删除 `public/images` 实体文件。若上传内容涉及隐私或版权撤回，需要增加磁盘/对象存储同步删除。
6. 生产必须显式配置 `CMS_ADMIN_API_KEY`；后台 UI 也应配置独立 `CMS_ADMIN_PASSWORD` 和 `CMS_ADMIN_SESSION_SECRET`，不要依赖 API key 复用为登录密码或 session secret。
