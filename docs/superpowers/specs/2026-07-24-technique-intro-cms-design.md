# TECHNIQUE 引言区与 CMS 完善设计

日期：2026-07-24

## 目标

在 TECHNIQUE 页面的 Hero 与工艺轮播之间增加一个独立的文字引言区，让两个视觉 section 之间形成自然过渡。同时完善该页面的 CMS，使 Hero、引言、轮播和 SEO 均可管理。

## 页面结构

页面保持以下顺序：

1. 现有 Hero
2. 新增引言区
3. 现有工艺轮播

Hero 的标题、正文、图片和背景效果保持不变。引言区只显示一个主标题和一段正文，不增加眉标、按钮、链接、分隔线或额外图片。

## 视觉设计

引言区采用居中排版，并继续显示页面现有的浅色工艺图纸背景，使 Hero 与轮播在视觉上属于同一个页面叙事。

- 主标题：响应式字号约 40–52px，使用页面现有标题字体和深蓝主色。
- 正文：响应式字号约 15–17px，最大宽度约 680px，使用现有正文字体。
- 标题与正文之间保留清晰但克制的间距。
- 引言区上下留白使用响应式尺寸：桌面端宽松，平板和手机端适当收紧。
- 长标题和多行正文允许自然换行，始终保持居中。
- 使用现有滚动显现动效；启用减少动态效果时取消过渡。

## 默认内容

韩文：

- 标题：`기술은 디테일에서 완성됩니다.`
- 正文：`대호는 설계부터 세공과 마감에 이르기까지, 각 공정의 작은 차이를 오래 남는 완성도로 연결합니다.`

英文：

- 标题：`Technique is perfected in the details.`
- 正文：`From design and craftsmanship to the final finish, DAEHO turns the smallest distinctions in every process into lasting refinement.`

## 组件边界

新增 `TechniqueIntroSection` 展示组件。组件只接收 `title` 和 `body`，负责语义结构、排版和显现动效，不负责数据读取或 CMS 保存。

TECHNIQUE 页面继续负责读取本地化页面内容，并按 Hero、引言、轮播的顺序组合三个 section。现有 `TechniqueCarouselSection` 不承担引言内容，避免文字与轮播交互逻辑耦合。

## 数据结构

在 `specialtyPages.techniqueRecords` 下新增独立对象：

```json
{
  "intro": {
    "title": "",
    "body": ""
  }
}
```

`intro.title` 和 `intro.body` 在韩文和英文内容中分别保存。Hero 和 `records.items` 的结构保持不变。

生产 CMS 中尚未存在 `intro` 时，页面和后台编辑器通过现有静态内容合并机制读取默认韩英文案，因此不需要数据库迁移。用户保存页面后，新字段随页面内容正常写入 CMS。

## CMS 结构

`mastery-technique` 页面继续使用现有整页编辑入口，并形成以下管理范围：

1. Hero：眉标、标题、正文、图片。
2. 中间引言：主标题、正文。
3. 工艺轮播：共用图片、韩英标题、韩英正文、添加、删除和排序。
4. SEO：韩英 SEO 标题、描述和分享图片。

引言字段使用现有通用韩英字段编辑器。轮播继续使用现有专用双语编辑器。两类编辑器共享同一次页面保存，但互不修改对方的数据。

引言区没有按钮或链接，因此不增加跳转字段。

## 数据保存与异常处理

- 页面保存继续使用现有 `savePageAction` 流程。
- 通用编辑器提交 `intro.title` 和 `intro.body`。
- 轮播专用规范化逻辑继续只处理 `records.items`。
- 保存引言时必须保留 Hero、轮播和 SEO 数据。
- CMS 缺少字段、读取失败或尚未初始化时使用静态默认内容，不显示空白模块，也不导致页面报错。

## 响应式与可访问性

- 引言区使用语义化 `section`、`h2` 和 `p`。
- 桌面、平板和手机均保持标题与正文居中。
- 文本容器限制最大宽度，避免宽屏正文行长过长。
- 中文、韩文和英文长文本均可换行，不产生横向溢出。
- 减少动态效果设置关闭显现动画。

## 验证

- 验证引言严格位于 Hero 与轮播之间。
- 验证韩英文默认标题和正文完整显示。
- 验证 CMS 显示并保存 `intro.title`、`intro.body`。
- 验证保存引言不会破坏 Hero、轮播项目、共享图片、排序或 SEO。
- 验证旧 CMS 数据没有 `intro` 时仍显示默认内容。
- 验证桌面、平板和手机端的间距、换行和居中效果。
- 运行相关 Node 测试、全量测试、Lint 和生产构建。
- 使用浏览器检查韩文与英文页面，并确认轮播交互保持正常。

## 不在本次范围

- 不修改 Hero 的内容结构或视觉。
- 不修改轮播交互、图片比例和 CMS 项目数量规则。
- 除已确认的引言区外，不增加跳转、按钮、额外图片或其他页面 section。
- 不进行数据库迁移。
